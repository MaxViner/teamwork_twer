## P0 — обязательное

### 1. Порядок этапов (`executor.py`) — ⚠️ частично

Ожидалось: `selected` из API нормализуется по кортежу `STAGES`, чтобы
порядок и состав нельзя было перепутать.

Что есть:

- `backend/app/APIGateway/pipeline.py` задаёт `STAGES` — единственный
  источник порядка.
- `backend/app/APIGateway/endpoints/jobs.py` при создании задания всегда
  вызывает `schedule(job_id, list(STAGES))`.
- Повтор этапа идёт через `_stages_for_retry(stage)`, который возвращает
  срезы того же `STAGES`.
- `executor.schedule()` просто перебирает переданный список и не
  фильтрует его по `STAGES`.

Чего нет: самой нормализации. Любой новый вызов `schedule()` с
произвольным списком (например, из будущего API выбора этапов) выполнит
этапы в переданном порядке и сможет запустить неизвестное имя. Сейчас
риск закрыт дисциплиной вызывающего кода, а не инвариантом.

Минимальная правка: в начале `schedule()` (или `execute()`) делать
`selected = [stage for stage in STAGES if stage in set(selected)]` и
логировать отброшенные имена.

### 2. Зависимости этапов (`REQUIRES`) — ❌ нет

Карты зависимостей в проекте нет. `pipeline.run_stage()` — плоский
`if stage == ...`, `executor._run_selected_stage()` проверяет только
`prepare`, и то лишь «завершён ли», без проверки поставщиков данных.

Последствия ровно те, что описаны в ТЗ: `location_evidence` и
`location_prompt` читают результаты `visual_analysis`, `place_profile`,
`audio_structure`, `speech`, но при падении поставщика не помечаются
`skipped`. Они строят «досье из пустоты»: пустой визуальный профиль,
нулевые улики, но формально завершённый этап. `_finish_job()` при этом
видит только `failed` и ставит `partial`, не объясняя, что данные
неполные.

Что нужно: словарь вида

```python
REQUIRES = {
    "ocr": ("prepare", "scenes"),
    "structure": ("speech", "ocr"),
    "place_profile": ("visual_analysis",),
    "location_evidence": ("visual_analysis", "place_profile", "audio_structure"),
    "location_prompt": ("location_evidence",),
}
```

и проверка перед запуском: если поставщик `failed` (или `skipped` по
причине сбоя), текущий этап получает `skipped` с машинной причиной
`upstream_failed:<stage>`, а не пустой результат.

### 3. Фильтр ASR-галлюцинаций — ❌ нет

`backend/app/services/audioService/speech.py` отдаёт все сегменты
Whisper как есть. Единственное, что есть, — пофреймовый флаг
`uncertain` у слов при средней вероятности ниже 0.5
(`_words()`), но:

- он не влияет на сегменты и наблюдения;
- нет проверки повторов;
- нет списка шаблонных галлюцинаций;
- нет поля `filtered: true`;
- фильтрация не подключена ни в `speech`, ни в `summary`, ни в
  `location_evidence`.

То есть известная фраза-галлюцинация («улице продолжил жара») попадёт
и в сводку, и в досье. Нужен отдельный модуль в `app/text.py` или рядом:
правила + маркировка, а не удаление, чтобы отчёт оставался проверяемым.

### 4. Валидация адресов геокодером — ❌ нет

`backend/app/services/geoInspectService/geo.py`:

- адрес вытаскивается регуляркой `ADDRESS_PATTERN` и сразу получает
  `confidence: 0.6` (строки ~445–461);
- `summarize()` повышает уверенность за повторяемость до `0.95`
  (строки ~799–816);
- Nominatim в этом пути не вызывается вообще.

Nominatim есть только в отдельном исследовательском CLI
`backend/app/services/mapService/tver_ghosts.py`, который к досье
отношения не имеет.

Следствие: критерий «ноль непроверенных адресов с confidence > 0.3»
нарушается по построению — любой адрес из OCR/речи сразу 0.6.
Нужен кэшируемый клиент Nominatim с таймаутом, статус
`verified/unverified`, `+0.2` при совпадении и координаты, `0.1` при
отсутствии совпадения.

## P1 — качество

### 5. Голосование за страны — ❌ нет

В `backend/app/services/geoInspectService/location.py` все визуальные,
дорожные, звуковые и сценические улики создаются с
`"country_hints": {}`. Голосуют только текстовые эвристики в `geo.py`
(бренды, телефоны, письменность, домены). На видео без GPS и без
читаемого текста `country_candidates` остаётся пустым.

Нужны эвристики «ландшафт → страны», «звук → страны», «объект → страны»
с весами 0.1–0.3. Данные для этого уже есть: `profile.landscape`,
`profile.season`, `sound_events`, `geo_clues`.

### 6. Новые `kind` улик — ❌ нет

Детектор гео-улик уже отдаёт 17 меток с `match_priority`, но в
`location.py` набор `kind` старый: `coordinates`, `created_at`,
`visual_profile`, `road_geometry`, `sound_event`, `audio_profile`,
`scene_profile`, `repetition`. Меток `landmark`, `architecture_style`,
`vegetation_species`, `road_sign` нет, `match_priority` в улики не
переносится.

То есть новый zero-shot слой собран, но к досье не подключён. Это
следующий по важности мост после P0.

### 7. Конфликт даты и сезона — ❌ нет

Сезон файла считается в `_metadata_context()` (`_season_from_date`),
сезон сцены — в `visualAnalysisService/metrics.py` и попадает в
`profile.season`. Сравнения между ними нет, улики `temporal_conflict`
нет. Дата из метаданных по-прежнему имеет confidence 0.5 независимо от
того, противоречит ли она картинке.

### 8. Resume по исходной выборке — ⚠️ частично

`selected` в `job.json` не сохраняется. При создании задания всегда
запускается полный `STAGES`; выбора подмножества этапов в API нет.
`request_resume()` вызывает `_remaining_stages(job)`, который идёт по
`STAGES` и возвращает хвост от первого незавершённого этапа.

Для текущего API это работает: выбор всегда полный. Но требование «resume
не должен запускать этапы, которых пользователь не выбирал» не выполнено
буквально — как только появится выбор этапов, resume его проигнорирует.
Нужно писать `selected` в `job.json` и пересекать остаток с ним.

### 9. Пауза — ✅ в основном

Что сделано правильно:

- `executor.execute()` и `_run_selected_stage()` ловят `PauseRequested`
  отдельным `except` до общего `except Exception`;
- `_report_progress()` проверяет `is_paused()` и поднимает
  `PauseRequested` из прогресс-колбэка — пауза кооперативная, без
  жёсткого убийства потока;
- `request_pause()` различает `queued/created` и `running`;
- `request_resume()` снимает `PAUSED_JOBS` и запускает остаток;
- `_recover_interrupted_jobs()` сохраняет паузу после перезапуска
  backend.

Остаточные риски:

- `PAUSED_JOBS` не очищается в `_finish_job()` и при удалении задания;
- если какой-то анализатор вызовет `progress()` внутри широкого
  `try/except Exception`, `PauseRequested` будет проглочен. В
  проверенных местах (`visualAnalysisService/stage.py`,
  `geoCluesService/service.py`, `placeProfileService/odometry.py`)
  прогресс вызывается вне per-frame `try`, но это не зафиксировано
  инвариантом или тестом.

## P2 — косметика

### 10. `history` в `job.json` — ❌ нет

`_begin_stage()` добавляет предыдущий прогон в `state["history"]` без
ограничения. При серии retry `job.json` растёт вместе с полными
результатами и наблюдениями каждого прогона. Нужно хранить 1–2
последних прогона.

### 11. Мёртвый `log_memory` — ❌ нет

`backend/app/APIGateway/executor.py` содержит `log_memory()`, но
вызовов нет. Функция и импорт `psutil` в этом модуле не используются.

### 12. Осознанный и аварийный `skipped` — ❌ нет

`_finish_job()` ставит `partial` только при наличии `failed`. Причина
`skipped` не кодируется: «этап выключен пользователем», «нет
аудиодорожки» и «не завершилась подготовка» выглядят одинаково.
Нужно поле `skip_reason` (`disabled`, `no_input`, `upstream_failed`) и
учёт аварийных пропусков в итоговом статусе.

## Критерий готовности из ТЗ

> Тестовое видео без GPS даёт досье с ≥ 3 видами голосующих улик и
> нулём непроверенных адресов с confidence > 0.3.

Сейчас **не выполняется**:

- голосующих видов улик меньше трёх: визуал, звук и сцена дают пустые
  `country_hints`;
- адреса не проверяются и сразу имеют confidence 0.6, то есть
  непроверенные адреса с confidence > 0.3 есть всегда.

Эти работы не входят в таблицу выше, но меняют состояние проекта:

- **Гео-улики.** Zero-shot стек Grounding DINO tiny + SAM2.1 hiera tiny,
  внутренний тайлинг 640/0.2, дедупликация швов, 17-меточный словарь,
  `geo_clues[]` с `polygon`, `visibility_fraction`, `shape_complexity`,
  `match_priority`, `frame_summary`. YOLO удалён.
- **Стадии.** `visual_analysis` и `place_profile` консолидированы,
  старые имена полей сохранены.
- **Одометрия.** ORB + essential matrix, CLAHE, USAC_MAGSAC, мягкий
  ratio-retry, диагностика пар. Метры честно помечены как оценка:
  `units: "relative"`, `metric_estimate: false`.
- **BEV v2.** Вместо облака всех детекций — маршрут и до 12 сильных
  якорей (`mode: "anchors"`, `schema_version: 2`). Слабые улики
  отбрасываются, одноимённые якоря сливаются.
- **Оболочка сервисов.** `serviceHub.py` с `VisualService`,
  `AudioService`, `LocationService` и `HUB`; `GET /api/dev/services`.
- **Дев-страницы.** `/dev/vision` (полный визуальный анализ),
  `/dev/video-lab`, `/dev/odometry` (одометрия + BEV, пара кадров),
  `/dev/map` (карт-исследование).
- **Задания.** Панель заданий — стековый список с удалением, паузой и
  возобновлением; удаление не сбрасывает выбранное чужое задание.

   снимает будущий класс ошибок).
2. **P0-2** — `REQUIRES` + `skip_reason: upstream_failed` (главный
   источник «мусора из пустоты»).

4. **P0-4** — Nominatim-валидация адресов с кэшем и таймаутом.
5. **P1-5** и **P1-6** — голосование стран и перенос гео-улик в досье:
   после этого появляется смысл в criterion готовности.
